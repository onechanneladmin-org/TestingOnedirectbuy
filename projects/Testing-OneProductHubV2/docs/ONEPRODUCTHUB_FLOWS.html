Flow 1 — Smoke Auth

Flow 2 — Auth & Access

Auth Enabled

Purpose

Harden identity: bad credentials, portal isolation, logout, session persistence, forgot password, signup forms, role selection, and guest guards on authenticated hashes.

Happy path

  1. Role selection shows Brand and Client choices.
  2. Brand and Client signup forms expose required fields.
  3. Forgot password UI opens from brand login.
  4. Brand session survives full page reload.
  5. Client Sign Out returns to public home (“Find Product Information”).

Alternate / negative paths

  • Wrong password → error; stay on login.
  • Brand credentials rejected on Client portal (and reverse).
  • Guest opening #/dashboard or #/products sees public home.

Flow 5 — Admin

Admin Enabled

Purpose

Platform operator surfaces: brands, clients, catalog, import/export, RBAC, settings. AI Studio is view-oriented (no brand-style Add Product).

Happy path

  1. Platform / Admin Dashboard overview.
  2. Brand Registry with review controls.
  3. Brand Directory — inspect a brand.
  4. Clients management.
  5. Product Catalog browse.
  6. Import Center and Export Center.
  7. AI Product Studio (admin; no add-product workflow).
  8. RBAC Access.
  9. Settings.

Alternate paths

  • Admin AI Studio may surface Add Product UI but block with platform-admin messaging.

Flow 6 — Brand

Brand Enabled

Purpose

Brand product workspace: create products, enrich in AI Studio, distribute, manage client access, data quality, import/export, changelog, settings, subscription.

Happy path

  1. Brand Dashboard (Workspace Overview).
  2. Add Product: open → fill name/SKU/price/brand/category/description/stock → Save → verify.
  3. Open product detail from Studio.
  4. AI Product Studio with filters.
  5. Distributions / channel sync.
  6. Client Access hub (pending / approved / revoked).
  7. Data Quality Dashboard.
  8. Export Center and Import Center.
  9. Product Change Log.
  10. Settings (+ #/settings?section=profile).
  11. Subscription plans.

Alternate paths

  • Category picker: select existing or Create "{name}".
  • Save validation if required fields empty.

Flow 8 — E2E Journeys

Cross-role Enabled

Purpose

Prove the core marketplace loop: Brand creates a product visible in Studio; Client and Brand see complementary access surfaces.

Journey A — Brand product lifecycle

  1. Sign in as Brand → Workspace Overview.
  2. Add Product (unique name/SKU, price, brand, category, description, stock) → Save.
  3. Assert product visible.
  4. AI Product Studio → same product/SKU visible.

Journey B — Client ↔ Brand access

  1. Client: Brand Directory → Request access / Edit draft when present.
  2. Brand: Client Access hub → pending/approved/revoked language.
sequenceDiagram participant Brand participant OPH participant Client Brand->>OPH: Create product Brand->>OPH: Visible in AI Product Studio Client->>OPH: Open Brand Directory Client->>OPH: Request or draft access Brand->>OPH: Client Access hub status

Preconditions

Brand + Client credentials. API rewrite via ensureApiRewrite when frontend still calls localhost:4000.
